# ClickPop — پرسش‌های باز

هر پرسش با اثرش روی معماری و **فرض جاری** مشخص شده. اگر فرض درست باشد، پاسخ لازم نیست.

## مسدودکنندهٔ فاز F1 (قبل از تولید کد)

**Q1 — محیط اجرا**
نسخهٔ دقیق PHP، WordPress، MySQL/MariaDB؟ VPS یا هاست اشتراکی؟ Redis در دسترس است؟ WP-Cron واقعی (system cron) فعال است یا cron مرورگری؟
*فرض جاری:* PHP 8.2+، WP 6.5+، MySQL 8، VPS با Redis، system cron هر دقیقه.
*اثر:* اگر Redis نباشد، RateLimiter و کش به transient می‌افتد (کندتر، اما کار می‌کند). اگر cron مرورگری باشد، همگام‌سازی وضعیت غیرقابل اتکا می‌شود و باید به system cron مهاجرت کرد.

**Q2 — تأمین‌کننده**
فقط `followeran.ir` یا چند تأمین‌کننده از روز اول؟ آیا کلید API تست/سندباکس در اختیار هست؟
*فرض جاری:* یک تأمین‌کننده، اما معماری چند-تأمین‌کننده.
*اثر:* بدون کلید تست، فاز F1 فقط با fixture ساختگی تست می‌شود و probeهای واقعی (Q5) عقب می‌افتند.

**Q3 — واحد و مقیاس `rate`** ← بحرانی‌ترین
در پاسخ `services`، مقدار `rate: 700000` یعنی:
- (الف) ۷۰۰٬۰۰۰ **تومان** به ازای **۱۰۰۰** واحد؟
- (ب) ۷۰۰٬۰۰۰ **ریال** به ازای ۱۰۰۰ واحد؟
- (ج) قیمت کل برای همان `min`؟
*فرض جاری:* (الف).
*اثر:* خطا در این فرض یعنی **ضریب ۱۰ خطا در قیمت هر سفارش** — یا فروش با یک‌دهم قیمت، یا ده برابر گران. تا تأیید، حالت `is_test=1` و فروش غیرفعال می‌ماند.

**Q4 — فیلد `service_rate`**
مقدار `"3.110"` چیست؟ نرخ دلاری؟ ضریب داخلی؟ امتیاز کیفیت؟
*فرض جاری:* استفاده نمی‌شود، فقط خام ذخیره می‌شود.

**Q5 — پارامتر `action=status` گروهی**
سند تأمین‌کننده متناقض است (`key`+`order` در جدول، `api`+`orders` در نمونهٔ پایتون). کدام درست است؟ سقف تعداد سفارش در یک فراخوان چقدر است؟
*فرض جاری:* درایور هر دو را پشتیبانی می‌کند و در نصب probe می‌زند؛ سقف دسته ۱۰۰.
*اثر:* اگر فقط تکی پشتیبانی شود، بار روی API تأمین‌کننده ۱۰۰ برابر می‌شود و باید فاصلهٔ همگام‌سازی افزایش یابد.

**Q6 — سقف نرخ فراخوانی تأمین‌کننده**
آیا rate limit اعلام‌شده‌ای دارند؟ بلاک شدن IP در صورت تخطی؟

## مسدودکنندهٔ فاز F2 (کیف پول و پرداخت)

**Q7 — درگاه‌های پرداخت**
دقیقاً کدام‌ها؟ (زرین‌پال / آیدی‌پی / نکست‌پی / زیبال / سایر). مرچنت‌کد و محیط تست موجود است؟ درگاه مستقیم بانکی هم در کار است؟
*فرض جاری:* زرین‌پال به‌عنوان درگاه اول، معماری درایورپذیر برای بقیه.

**Q8 — واحد پول نمایشی و مالیات**
نمایش به تومان (فرض) یا ریال؟ مالیات بر ارزش افزوده روی خرید اعمال می‌شود؟ صدور صورتحساب رسمی لازم است؟
*اثر:* مالیات یک ستون و یک قاعدهٔ محاسباتی جدید در `cp_orders` می‌خواهد و پس از شروع فروش، افزودنش پرهزینه است.

**Q9 — سیاست بازگشت وجه**
بازگشت وجه سفارش ناقص (`Partial`) به کیف پول یا قابل برداشت به حساب بانکی؟ حداقل مبلغ شارژ؟ سقف موجودی؟
*فرض جاری:* فقط بازگشت به کیف پول؛ بدون برداشت نقدی.

## مسدودکنندهٔ فاز F5/F6

**Q10 — احراز هویت**
ورود با موبایل+OTP یا ایمیل+رمز؟ پنل پیامکی کدام است (کاوه‌نگار / SMS.ir / ملی‌پیامک)؟ ثبت‌نام آزاد است یا با تأیید؟
*فرض جاری:* موبایل + OTP، درایور پیامک انتزاعی.

**Q11 — مهاجرت**
سایت یا پنل فعلی وجود دارد؟ کاربران، موجودی کیف پول و سفارش‌های تاریخی باید منتقل شوند؟
*اثر:* مهاجرت موجودی کیف پول باید به‌صورت ردیف‌های `type='adjust'` در دفتر کل انجام شود، نه `UPDATE` مستقیم — این یک فاز مستقل است.

**Q12 — الزامات قانونی**
نماد اعتماد الکترونیکی (اینماد)، ساماندهی، درج شرایط و قوانین، احراز هویت کاربر (KYC) لازم است؟

## غیرمسدودکننده (تصمیم تا فاز F7)

**Q13 — چندزبانه:** ترجمهٔ واقعی محتوا یا فقط زیرساخت آماده؟ Polylang یا WPML؟
*فرض جاری:* زیرساخت آماده + فارسی کامل؛ Polylang.

**Q14 — ~~دامنهٔ المنتور~~:** بسته شد. صفحه‌ساز حذف شد؛ صفحه‌ها قالب PHP‌اند و متن‌ها از پنل «محتوای سایت» می‌آیند.

**Q15 — بلاگ و محتوا:** وبلاگ در فاز اول هست؟ چند صفحهٔ فرود سرویس برنامه‌ریزی شده؟

**Q16 — اعلان‌ها:** پیامک/ایمیل روی چه رویدادهایی؟ (ثبت سفارش، تکمیل، شارژ موفق، پاسخ تیکت) — هزینهٔ پیامک روی حجم بالا قابل توجه است.
