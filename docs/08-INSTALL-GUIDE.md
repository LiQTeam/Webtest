# راهنمای نصب و راه‌اندازی روی وردپرس

از صفر تا سفارش اول. هر مرحله دقیقاً یک کار انجام می‌دهد و در انتهایش یک «معیار پذیرش» دارد؛ اگر معیار برقرار نبود، سراغ مرحلهٔ بعد نروید.

---

## ۰. پیش‌نیازها

| مورد | حداقل | توصیه‌شده |
|---|---|---|
| PHP | 8.1 | 8.3 با OPcache |
| WordPress | 6.5 | آخرین نسخه |
| MySQL / MariaDB | 8.0 / 10.6 (موتور **InnoDB**) | همان + Redis برای object cache |
| SSL | اجباری | Let's Encrypt یا گواهی معتبر |
| اکستنشن PHP | `openssl`, `curl`, `mbstring`, `json` | + `intl` |

> **InnoDB اجباری است.** کیف پول به تراکنش و قفل ردیفی نیاز دارد؛ روی MyISAM دو سفارش همزمان
> می‌توانند موجودی را منفی کنند و مغایرت مالی بی‌صدا بماند.

بررسی در **phpMyAdmin ← تب SQL**:

```sql
SHOW TABLE STATUS WHERE Engine <> 'InnoDB';
```

**باید خالی برگردد.**

### اگر جدول‌ها MyISAM بودند

روی بعضی میزبان‌های اشتراکی `default_storage_engine` هنوز MyISAM است و کل وردپرس با MyISAM نصب می‌شود.

**۱. اول پشتیبان بگیرید** — phpMyAdmin ← Export ← Quick ← SQL ← Go.

**۲. تبدیل کنید** (روی سایت تازه‌نصب چند ثانیه طول می‌کشد):

```sql
ALTER TABLE `click_commentmeta`        ENGINE=InnoDB ROW_FORMAT=DYNAMIC;
ALTER TABLE `click_comments`           ENGINE=InnoDB ROW_FORMAT=DYNAMIC;
ALTER TABLE `click_links`              ENGINE=InnoDB ROW_FORMAT=DYNAMIC;
ALTER TABLE `click_options`            ENGINE=InnoDB ROW_FORMAT=DYNAMIC;
ALTER TABLE `click_postmeta`           ENGINE=InnoDB ROW_FORMAT=DYNAMIC;
ALTER TABLE `click_posts`              ENGINE=InnoDB ROW_FORMAT=DYNAMIC;
ALTER TABLE `click_term_relationships` ENGINE=InnoDB ROW_FORMAT=DYNAMIC;
ALTER TABLE `click_term_taxonomy`      ENGINE=InnoDB ROW_FORMAT=DYNAMIC;
ALTER TABLE `click_termmeta`           ENGINE=InnoDB ROW_FORMAT=DYNAMIC;
ALTER TABLE `click_terms`              ENGINE=InnoDB ROW_FORMAT=DYNAMIC;
ALTER TABLE `click_usermeta`           ENGINE=InnoDB ROW_FORMAT=DYNAMIC;
ALTER TABLE `click_users`              ENGINE=InnoDB ROW_FORMAT=DYNAMIC;
```

پیشوند `click_` را با پیشوند خودتان جایگزین کنید، یا فهرست را خودکار بسازید:

```sql
SELECT CONCAT('ALTER TABLE `', TABLE_NAME, '` ENGINE=InnoDB ROW_FORMAT=DYNAMIC;') AS stmt
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = DATABASE() AND ENGINE = 'MyISAM';
```

**۳. دوباره بررسی کنید** — کوئری `SHOW TABLE STATUS` باید خالی برگردد.

**۴. از میزبان بخواهید پیش‌فرض سرور را عوض کند** تا افزونه‌های دیگر هم MyISAM نسازند:

```ini
default_storage_engine = InnoDB
```

> جدول‌های خود کلیک‌پاپ صریحاً با `ENGINE=InnoDB` ساخته می‌شوند و به پیش‌فرض سرور وابسته نیستند.
> اگر با این حال جدولی InnoDB نبود، افزونه در پیشخوان هشدار قرمز می‌دهد و دکمهٔ **تبدیل یک‌کلیکی** نشان می‌دهد
> (فقط جدول‌های `cp_` را لمس می‌کند؛ جدول‌های هستهٔ وردپرس دست‌نخورده می‌مانند).

## ۱. آماده‌سازی `wp-config.php`

> ⚠️ **این مرحله بیش از هر مرحلهٔ دیگری خراب می‌شود.** سه قانون زیر را قبل از ویرایش بخوانید،
> وگرنه محتوای `wp-config.php` روی صفحهٔ اصلی سایت **برای همه چاپ می‌شود** — از جمله رمز دیتابیس.

### قانون‌های غیرقابل مذاکره

| # | قانون | چرا |
|---|---|---|
| ۱ | خط اول فایل باید دقیقاً `<?php` باشد — **بدون فاصله، بدون خط خالی، بدون BOM** | هر بایتی پیش از `<?php` خروجی HTML است و همهٔ هدرها را می‌شکند |
| ۲ | بلوک را **داخل** بخش PHP بگذارید، **بالای** خط `/* That's all, stop editing! */` | پایین‌تر از آن، وردپرس قبلاً بارگذاری شده و ثابت‌ها بی‌اثرند |
| ۳ | انتهای فایل **نباید** `?>` داشته باشد | یک خط خالی بعد از `?>` همان فاجعهٔ قانون ۱ را می‌سازد |
| ۴ | فایل را **UTF-8 without BOM** ذخیره کنید و **کاراکتر فارسی داخل آن نگذارید** | ویرایشگرهای هاست گاهی متن فارسی را با انکودینگ اشتباه ذخیره می‌کنند |

### بلوکی که باید اضافه شود

فقط همین شش خط — بدون توضیح فارسی، بدون کاراکتر خاص:

```php
/* ClickPop start */
define( 'CLICKPOP_ENCRYPTION_KEY', 'PUT_YOUR_44_CHAR_KEY_HERE' );
define( 'DISABLE_WP_CRON', true );
define( 'WP_DEBUG', false );
define( 'WP_DEBUG_DISPLAY', false );
define( 'WP_DEBUG_LOG', true );
/* ClickPop end */
```

فایل آمادهٔ کپی: `dist/wp-config-clickpop-block.txt` (کاملاً ASCII، بدون BOM).

### تولید کلید

**با SSH:**
```bash
php -r "echo base64_encode(random_bytes(32)), PHP_EOL;"
```

**بدون SSH:** فایل موقت `key.php` در ریشهٔ سایت بسازید با محتوای
`<?php echo base64_encode(random_bytes(32));`
آدرسش را باز کنید، خروجی را کپی کنید، **بعد فایل را حتماً پاک کنید.**

### جای درست بلوک

```php
<?php                                   ← خط ۱، بدون هیچ چیز قبلش
define( 'DB_NAME', '...' );
define( 'DB_USER', '...' );
define( 'DB_PASSWORD', '...' );
define( 'DB_HOST', 'localhost' );

$table_prefix = 'click_';

/* ClickPop start */                    ← بلوک اینجا
define( 'CLICKPOP_ENCRYPTION_KEY', '...' );
define( 'DISABLE_WP_CRON', true );
define( 'WP_DEBUG', false );
define( 'WP_DEBUG_DISPLAY', false );
define( 'WP_DEBUG_LOG', true );
/* ClickPop end */

/* That's all, stop editing! Happy publishing. */

if ( ! defined( 'ABSPATH' ) ) {
	define( 'ABSPATH', __DIR__ . '/' );
}

require_once ABSPATH . 'wp-settings.php';
                                        ← اینجا تمام. بدون ‎?>‎
```

**معیار پذیرش:** صفحهٔ اصلی و پیشخوان باز می‌شوند و **هیچ متنی از داخل فایل روی صفحه دیده نمی‌شود.**
اگر متن یا `Warning: Cannot modify header information` دیدید، به بخش «عیب‌یابی اضطراری» انتهای همین سند بروید.

## ۲. نصب تم و افزونه

دو فایل زیپ در پوشهٔ `dist/` مخزن آماده است:

- `clickpop-theme.zip`
- `clickpop-core.zip`

### روش الف — پیشخوان وردپرس (ساده‌ترین)

1. **نمایش ← پوسته‌ها ← افزودن ← بارگذاری پوسته** → `clickpop-theme.zip` → نصب → **فعال‌سازی**
2. **افزونه‌ها ← افزودن ← بارگذاری افزونه** → `clickpop-core.zip` → نصب → **فعال‌سازی**

### روش ب — FTP / SSH

```bash
unzip clickpop-theme.zip -d /path/to/wp-content/themes/
unzip clickpop-core.zip  -d /path/to/wp-content/plugins/
chown -R www-data:www-data /path/to/wp-content/themes/clickpop
chown -R www-data:www-data /path/to/wp-content/plugins/clickpop-core
```
سپس از پیشخوان هر دو را فعال کنید.

### روش ج — WP-CLI

```bash
wp theme install clickpop-theme.zip --activate
wp plugin install clickpop-core.zip --activate
```

**معیار پذیرش:** در پیشخوان منوی جدید **کلیک‌پاپ** با آیکن نمودار دیده می‌شود.

### پیشوند جدول

افزونه پیشوند را از `$wpdb->prefix` می‌خواند، یعنی **هر پیشوندی که در `wp-config.php` تنظیم کرده‌اید**.
نام جدول = `{پیشوند شما}` + `cp_` + نام.

| پیشوند شما | نام جداول ساخته‌شده |
|---|---|
| `wp_` | `wp_cp_orders`, `wp_cp_wallets`, … |
| `click_` | `click_cp_orders`, `click_cp_wallets`, … |

بررسی (پیشوند خودتان را بگذارید):

```sql
SHOW TABLES LIKE 'click_cp_%';
-- باید ۱۱ ردیف برگردد
```

فهرست کامل ۱۱ جدول:
`cp_providers` · `cp_categories` · `cp_services` · `cp_pricing_rules` · `cp_wallets` ·
`cp_transactions` · `cp_orders` · `cp_tickets` · `cp_ticket_messages` · `cp_audit_log` · `cp_api_log`

> هیچ نام جدولی در کد سخت‌کد نشده است. تغییر پیشوند بعد از نصب پشتیبانی نمی‌شود (مثل خود وردپرس) — پیشوند را قبل از فعال‌سازی نهایی کنید.

## ۳. اتصال به سرویس‌دهندهٔ SMM

**کلیک‌پاپ ← تنظیمات**:

| فیلد | مقدار برای فالووران |
|---|---|
| آدرس API | `https://my.followeran.ir/api/v2` |
| کلید API | کلید پنل خودتان (فقط یک‌بار وارد می‌شود، بعد ماسک نمایش داده می‌شود) |
| واحد قیمت | `1000` — یعنی `rate` قیمت هر ۱۰۰۰ عدد است |
| واحد پول | `IRT` (تومان) |
| وضعیت | فعال ✅ |

> ⚠️ **قبل از فروش واقعی، «واحد قیمت» را تأیید کنید.** اگر `rate` در پنل شما قیمت هر ۱ عدد باشد (نه هر ۱۰۰۰)، این عدد را روی `1` بگذارید. اشتباه در این فیلد یعنی ضریب ۱۰۰۰ خطا در قیمت هر سفارش. راه تأیید: یک سرویس ارزان را با `is_test=1` سفارش دهید و مبلغ کسرشده در پنل سرویس‌دهنده را با محاسبهٔ خودتان مقایسه کنید.

**ذخیره** بزنید، بعد **کلیک‌پاپ ← نمای کلی ← همگام‌سازی دستی سرویس‌ها**.

**معیار پذیرش:** در **کلیک‌پاپ ← سرویس‌ها و قیمت** فهرست سرویس‌ها با قیمت تمام‌شده و قیمت فروش دیده می‌شود و ستون «سود» هیچ‌جا منفی نیست.

## ۴. قاعدهٔ سود

همان صفحهٔ تنظیمات:

| فیلد | معنی | پیشنهاد شروع |
|---|---|---|
| درصد سود | روی قیمت تمام‌شده اعمال می‌شود | `20` |
| گام گرد کردن | قیمت نهایی به این گام گرد می‌شود (به بالا) | `100` تومان |
| آستانهٔ جهش قیمت | اگر قیمت سرویس‌دهنده بیش از این درصد بپرد، سرویس خودکار از فروش خارج و به صف بازبینی می‌رود | `20` |

فرمول: `قیمت فروش = ceil( (قیمت تمام‌شده + سود) / گام ) × گام`

قاعده‌های دقیق‌تر (هر برند، هر دسته، هر سرویس) در جدول `{پیشوند}cp_pricing_rules` با اولویت `service > category > brand > global` قابل درج‌اند.

**معیار پذیرش:** بعد از تغییر درصد سود و اجرای دوبارهٔ همگام‌سازی، ستون «قیمت فروش» تغییر کرده باشد.

## ۵. درگاه پرداخت (زرین‌پال)

همان صفحهٔ تنظیمات، بخش درگاه:

1. تیک **فعال‌سازی** را بزنید.
2. **کد پذیرنده** را وارد کنید (۳۶ کاراکتر، از پنل زرین‌پال).
3. برای تست، تیک **محیط تست** را بزنید.
4. حداقل/حداکثر شارژ را تعیین کنید.

آدرس بازگشت به‌صورت خودکار ثبت می‌شود:
```
https://clickpop.ir/clickpop-payment/zarinpal/
```
اگر بعد از فعال‌سازی خطای ۴۰۴ گرفتید: **تنظیمات ← پیوندهای یکتا** را باز کنید و بدون تغییر **ذخیره** بزنید (بازنویسی قواعد rewrite).

**معیار پذیرش:** در داشبورد کاربر، تب «کیف پول» → مبلغ → «انتقال به درگاه» شما را به صفحهٔ زرین‌پال می‌برد و بعد از پرداخت با پیام سبز برمی‌گردد.

## ۶. ساخت صفحهٔ داشبورد

1. **برگه‌ها ← افزودن برگه** با عنوان «داشبورد».
2. در محتوا فقط این شورتکد را بگذارید:
   ```
   [clickpop_dashboard]
   ```
3. در پنل کناری، **قالب** را روی **داشبورد کلیک‌پاپ** بگذارید (تمام‌عرض، بدون سایدبار).
4. انتشار.
5. برگردید به **کلیک‌پاپ ← تنظیمات ← صفحهٔ داشبورد** و همین برگه را انتخاب و ذخیره کنید.

شورتکدهای دیگر:

| شورتکد | کاربرد |
|---|---|
| `[clickpop_dashboard]` | داشبورد کامل: سفارش جدید، سفارش‌ها، کیف پول، تیکت |
| `[clickpop_order_form]` | فقط فرم ثبت سفارش (برای صفحهٔ فرود) |
| `[clickpop_services]` | جدول عمومی سرویس‌ها و قیمت‌ها |

**معیار پذیرش:** با یک حساب کاربری عادی وارد شوید؛ داشبورد با موجودی صفر و فرم سفارش پرشده از سرویس‌های واقعی دیده می‌شود.

## ۷. کرون سیستمی (اجباری)

بدون این مرحله، وضعیت سفارش‌ها به‌روز نمی‌شود و بازگشت وجه خودکار اجرا نمی‌شود.

```bash
crontab -e
```
این خط را اضافه کنید (هر دقیقه):
```
* * * * * cd /path/to/wordpress && /usr/bin/php wp-cron.php >/dev/null 2>&1
```
یا با WP-CLI:
```
* * * * * /usr/local/bin/wp cron event run --due-now --path=/path/to/wordpress >/dev/null 2>&1
```

کارهای زمان‌بندی‌شده:

| هوک | دوره | کار |
|---|---|---|
| `clickpop_sync_services` | هر ۶ ساعت | همگام‌سازی فهرست و قیمت سرویس‌ها |
| `clickpop_sync_orders` | هر ۵ دقیقه | به‌روزرسانی وضعیت سفارش‌ها + بازگشت وجه ناقص/لغو |
| `clickpop_reconcile_orphans` | هر ۵ دقیقه | تعیین تکلیف سفارش‌هایی که پاسخ سرویس‌دهنده گم شده |

**معیار پذیرش:**
```bash
wp cron event list | grep clickpop
```
هر سه هوک با زمان اجرای آینده دیده شوند.

## ۸. محتوای سایت، منو و لوگو

این تم به هیچ صفحه‌سازی نیاز ندارد. صفحهٔ اصلی با قالب PHP رندر می‌شود و متن‌هایش را از پنل می‌گیرد.

### ۸.۱ محتوای صفحهٔ اصلی

**کلیک‌پاپ ← محتوای سایت**

| بخش | چه چیزی ویرایش می‌شود |
|---|---|
| هیرو | برچسب بالای عنوان، عنوان اصلی، توضیح، متن و لینک دو دکمه |
| سرویس‌ها | عنوان و توضیح بخش (کارت‌ها و قیمت‌ها خودکار از دیتابیس می‌آیند) |
| مراحل کار | تا ۴ مرحله با عنوان و توضیح |
| آمارها | تا ۴ عدد با برچسب |
| پرسش‌های پرتکرار | تا ۴ پرسش و پاسخ — داده‌ساختار `FAQPage` گوگل خودکار تولید می‌شود |
| فراخوان پایانی | عنوان، توضیح، متن دکمه |
| تماس و شبکه‌ها | تلفن، ایمیل، نشانی، اینستاگرام، تلگرام، ایکس |

هر فیلدی که خالی بگذارید، مقدار پیش‌فرض تم را می‌گیرد؛ صفحه هیچ‌وقت خالی نمی‌ماند.
ردیف‌های خالی در فهرست‌های تکرارشونده نادیده گرفته می‌شوند.

### ۸.۲ لوگو و منو

1. **نمایش ← سفارشی‌سازی ← هویت سایت** → لوگو.
   اگر لوگو نگذارید، لوگوی SVG برند به‌صورت درون‌خطی رندر می‌شود — یک درخواست شبکه کمتر و برای LCP بهتر است.
2. **نمایش ← فهرست‌ها** → سه جایگاه: «منوی اصلی»، «منوی فوتر»، «منوی قوانین».
3. **تنظیمات ← خواندن** → یک برگه را صفحهٔ اصلی کنید.
   محتوای همان برگه (اگر چیزی داشته باشد) بین بخش سرویس‌ها و مراحل نمایش داده می‌شود.

### ۸.۳ صفحهٔ فهرست قیمت‌ها

برگهٔ جدید بسازید، در **ویژگی‌های برگه ← قالب** گزینهٔ **فهرست سرویس‌ها و قیمت‌ها** را انتخاب کنید.
جدول کامل سرویس‌ها، دسته‌بندی‌شده بر اساس پلتفرم، خودکار رندر می‌شود.

## ۹. پنل مدیریت

همه‌چیز زیر منوی **کلیک‌پاپ** در پیشخوان است.

| صفحه | چه کاری می‌کند |
|---|---|
| **نمای کلی** | آمار ۳۰ روز (سفارش، فروش، سود ناخالص)، سلامت سرویس‌دهنده، وضعیت مدارشکن، موتور جدول‌ها، دکمهٔ همگام‌سازی دستی |
| **سفارش‌ها** | فهرست با فیلتر وضعیت و جست‌وجو روی لینک/شناسه/نام سرویس. کلیک روی هر سفارش → نمای جزئیات |
| **سرویس‌ها و قیمت** | قیمت تمام‌شده، قیمت فروش، سود هر سرویس، بازهٔ مجاز، وضعیت |
| **تیکت‌ها** | فهرست با شمارندهٔ تیکت‌های باز کنار منو، رشتهٔ گفت‌وگو، پاسخ، یادداشت داخلی، تغییر وضعیت و اولویت، واگذاری |
| **محتوای سایت** | متن‌های صفحهٔ اصلی (بخش ۸.۱) |
| **کیف پول کاربران** | تعدیل دستی موجودی با دلیل اجباری + ۵۰ تراکنش آخر |
| **تنظیمات** | سرویس‌دهنده، قاعدهٔ سود، درگاه پرداخت، برگهٔ داشبورد |

### نمای جزئیات سفارش

سه عمل در ستون کناری:

1. **بررسی وضعیت از سرویس‌دهنده** — همین حالا `action=status` می‌زند، بدون انتظار برای کرون.
2. **تغییر دستی وضعیت** — فقط برچسب را عوض می‌کند و **هیچ پولی جابه‌جا نمی‌کند**. این جداسازی عمدی است تا یک تغییر وضعیت اشتباه به پرداخت ناخواسته تبدیل نشود.
3. **بازگشت وجه** — دکمهٔ جدا با تأییدیه. مبلغ از همان مسیر امن دفتر کل برمی‌گردد و یک ردیف دائمی ثبت می‌شود.

پایین صفحه، تمام تراکنش‌های مالی همان سفارش با موجودی قبل و بعد نمایش داده می‌شود.

### تیکت‌ها

- **یادداشت داخلی** با تیک مخصوص ثبت می‌شود و **هرگز به کاربر نشان داده نمی‌شود** (نه در داشبورد، نه در API).
- **پاسخ‌های آماده** با یک کلیک به متن اضافه می‌شوند.
- تیک «بعد از ارسال ببند» تیکت را در همان مرحله می‌بندد.
- متن پیام‌ها **متن ساده** ذخیره می‌شود، نه HTML — بردار XSS ذخیره‌شده در پنل ادمین کاملاً حذف است.

هر عمل حساس (پاسخ، تغییر وضعیت، بازگشت وجه، تعدیل موجودی، ویرایش محتوا) در جدول `{پیشوند}cp_audit_log` با شناسهٔ کاربر، IP و زمان ثبت می‌شود.

## ۱۰. تست پذیرش قبل از افتتاح

این هفت تست را دقیقاً اجرا کنید. هرکدام یک باگ واقعی را می‌گیرد.

| # | تست | نتیجهٔ درست |
|---|---|---|
| ۱ | با کاربر A وارد شوید، سفارش ثبت کنید. با کاربر B آدرس `/wp-json/clickpop/v1/orders/{id}` سفارش A را باز کنید | `404` — نه دادهٔ سفارش |
| ۲ | موجودی را روی مبلغی بگذارید که فقط یک سفارش کفاف دهد، و دکمهٔ ثبت را ۵ بار سریع بزنید | دقیقاً **یک** سفارش ثبت شود، موجودی یک بار کسر شود |
| ۳ | یک شارژ موفق انجام دهید، سپس آدرس بازگشت (`?Authority=…`) را دوباره در مرورگر باز کنید | پیام «قبلاً ثبت شده» — موجودی دوباره اضافه **نشود** |

## ۱۱. بهینه‌سازی نهایی (اختیاری ولی مؤثر)

```bash
# Redis برای object cache
wp plugin install redis-cache --activate && wp redis enable

# ایندکس‌ها را بررسی کنید (پیشوند خودتان را بگذارید)
wp db query "SHOW INDEX FROM click_cp_orders"
```

روی Nginx، بایپس کش برای کاربران واردشده:
```nginx
set $skip_cache 0;
if ($http_cookie ~* "wordpress_logged_in") { set $skip_cache 1; }
location ~ ^/clickpop-payment/ { set $skip_cache 1; }
```

فونت: فایل `Vazirmatn-Variable.woff2` را در `wp-content/themes/clickpop/assets/fonts/` بگذارید تا `preload` فعال شود (اگر نباشد، تم بی‌صدا از فونت سیستم استفاده می‌کند).

## ۱۲. عیب‌یابی

| نشانه | علت محتمل | راه‌حل |
|---|---|---|
| «سرویس‌دهندهٔ فعالی تنظیم نشده» | کلید API ذخیره نشده | تنظیمات ← کلید API را دوباره وارد و ذخیره کنید |
| فهرست سرویس خالی | همگام‌سازی اجرا نشده یا کلید غلط | نمای کلی ← همگام‌سازی دستی؛ ستون «تأخیر آخرین پاسخ» را ببینید |
| وضعیت سفارش‌ها به‌روز نمی‌شود | کرون سیستمی تنظیم نشده | مرحلهٔ ۷ |
| بازگشت از درگاه ۴۰۴ | قواعد rewrite بازنویسی نشده | تنظیمات ← پیوندهای یکتا ← ذخیره |
| «موجودی کیف پول کافی نیست» با وجود موجودی | مبلغ سفارش با قیمت جدید محاسبه شده | همگام‌سازی را اجرا و قیمت را در صفحهٔ سرویس‌ها بررسی کنید |
| قیمت‌ها ۱۰ برابر یا یک‌دهم | «واحد قیمت» یا «واحد پول» اشتباه | مرحلهٔ ۳ — هشدار قرمز |
| هشدار کلید رمزنگاری در پیشخوان | `CLICKPOP_ENCRYPTION_KEY` تعریف نشده | مرحلهٔ ۱ |
| سرویس با وضعیت `review` | قیمت سرویس‌دهنده بیش از آستانه پریده | قیمت را بررسی و در دیتابیس وضعیت را به `active` برگردانید |

لاگ فراخوان‌های API در جدول `{پیشوند}cp_api_log` است (بدون کلید API و بدون لینک کاربر). گزارش ممیزی اعمال حساس در `{پیشوند}cp_audit_log`.

## ۱۳. آنچه هنوز پیاده نشده

صادقانه، تا تصمیم شما:

- **ورود با موبایل و کد یک‌بارمصرف (OTP):** طراحی‌اش در سند معماری هست، اما پیاده‌سازی به انتخاب پنل پیامکی نیاز دارد. فعلاً ورود استاندارد وردپرس کار می‌کند.
- **درگاه‌های آیدی‌پی / نکست‌پی:** معماری درایورپذیر آماده است؛ افزودن هرکدام حدود ۱۰۰ خط است.
- **صفحه‌بندی جدول سفارش‌ها در داشبورد کاربر:** فعلاً ۲۰ سفارش آخر (در پنل مدیریت صفحه‌بندی کامل هست).
- **ترجمهٔ en/ru/zh:** همهٔ رشته‌ها i18n-شده‌اند اما فایل `.po` هنوز تولید نشده.
- **بیش از ۴ ردیف در فهرست‌های محتوا:** فرم فعلاً ۴ ردیف ثابت دارد (مراحل، آمار، پرسش‌ها). افزایشش یک تغییر یک‌خطی است.

## عیب‌یابی اضطراری — محتوای `wp-config.php` روی سایت چاپ می‌شود

**نشانه:** بالای صفحهٔ اصلی و پیشخوان، متن خام فایل پیکربندی و چند
`Warning: Cannot modify header information - headers already sent by (output started at .../wp-config.php:1)` دیده می‌شود.

**این یک نشت اطلاعات است، نه فقط یک خطای ظاهری.** هرچه در آن فایل بوده — از جمله رمز دیتابیس و
کلید رمزنگاری — برای هر بازدیدکننده‌ای قابل خواندن بوده است.

### گام ۱ — سایت را از دسترس خارج کنید (اختیاری ولی توصیه‌شده)

در `.htaccess` ریشه، موقتاً فقط IP خودتان را مجاز کنید، یا سایت را روی حالت تعمیر بگذارید.

### گام ۲ — فایل را درست کنید

در File Manager هاست، `wp-config.php` را با **Edit** (نه Code Editor) باز کنید و مطمئن شوید:

- خط ۱ دقیقاً `<?php` است — مکان‌نما را قبل از `<` ببرید؛ نباید فاصله یا خط خالی باشد.
- بلوک ClickPop **بالای** خط `That's all, stop editing!` و **پایین** `$table_prefix` است.
- هیچ `?>` در فایل نیست (با Ctrl+F جست‌وجو کنید).
- هیچ متن فارسی داخل فایل نیست.

اگر مطمئن نیستید: فایل را کامل انتخاب و حذف کنید، و نسخهٔ تمیز را از روی الگوی بخش ۱ بازنویسی کنید.
مقادیر `DB_NAME` / `DB_USER` / `DB_PASSWORD` / `$table_prefix` را از پشتیبان یا از پنل هاست بردارید.

### گام ۳ — چیزهایی که لو رفته را عوض کنید

| مورد | کار |
|---|---|
| کلید رمزنگاری | کلید **جدید** تولید کنید و جایگزین کنید. کلید قبلی سوخته است. |
| رمز دیتابیس | در cPanel → MySQL Databases → رمز کاربر را عوض کنید، بعد `DB_PASSWORD` را به‌روز کنید. |
| نمک‌های وردپرس | مقادیر `AUTH_KEY` تا `NONCE_SALT` را از https://api.wordpress.org/secret-key/1.1/salt/ بگیرید و جایگزین کنید (همهٔ کاربران یک بار خارج می‌شوند). |
| کلید API سرویس‌دهنده | اگر افزونه نصب بوده و کلید ذخیره شده، در پنل فالووران کلید را باطل و کلید تازه بسازید. |

### گام ۴ — تأیید

- صفحهٔ اصلی: هیچ متن خامی نباشد.
- پیشخوان: هشدار «کلید رمزنگاری تعریف نشده» دیده **نشود** (یعنی ثابت واقعاً اجرا شده).
- **کلیک‌پاپ ← نمای کلی**: ردیف «موتور جدول‌های کلیک‌پاپ» باید `InnoDB ✓` باشد.
