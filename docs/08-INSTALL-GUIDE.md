# راهنمای نصب و راه‌اندازی روی وردپرس

از صفر تا سفارش اول. هر مرحله دقیقاً یک کار انجام می‌دهد و در انتهایش یک «معیار پذیرش» دارد؛ اگر معیار برقرار نبود، سراغ مرحلهٔ بعد نروید.

---

## ۰. پیش‌نیازها

| مورد | حداقل | توصیه‌شده |
|---|---|---|
| PHP | 8.1 | 8.3 با OPcache |
| WordPress | 6.5 | آخرین نسخه |
| MySQL / MariaDB | 8.0 / 10.6 (موتور **InnoDB**) | همان + Redis برای object cache |
| افزونهٔ صفحه‌ساز | — | Elementor (رایگان) · Elementor Pro برای Theme Builder |
| SSL | اجباری | Let's Encrypt یا گواهی معتبر |
| اکستنشن PHP | `openssl`, `curl`, `mbstring`, `json` | + `intl` |

> **InnoDB اجباری است.** کیف پول به تراکنش و قفل ردیفی نیاز دارد؛ روی MyISAM دادهٔ مالی خراب می‌شود.
> بررسی: `SHOW TABLE STATUS WHERE Engine <> 'InnoDB';` باید خالی برگردد.

## ۱. آماده‌سازی `wp-config.php`

پیش از هر چیز این خطوط را **بالای** خط `/* That's all, stop editing! */` اضافه کنید:

```php
/* ── ClickPop ───────────────────────────────────────────── */

// کلید رمزنگاری کلید API سرویس‌دهنده. یک‌بار تولید کنید و هرگز عوض نکنید.
// تولید: در ترمینال ->  php -r "echo base64_encode(random_bytes(32));"
define( 'CLICKPOP_ENCRYPTION_KEY', 'اینجا-کلید-۴۴-کاراکتری-خودتان' );

// در محیط تست فعال کنید تا سفارش‌ها با is_test=1 به سرویس‌دهنده بروند.
// define( 'CLICKPOP_PROVIDER_TEST_MODE', true );

// کرون مرورگری را خاموش کنید و کرون سیستمی بگذارید (مرحلهٔ ۷).
define( 'DISABLE_WP_CRON', true );

// در پروداکشن خطا نمایش داده نشود.
define( 'WP_DEBUG', false );
define( 'WP_DEBUG_DISPLAY', false );
define( 'WP_DEBUG_LOG', true );
```

> بدون `CLICKPOP_ENCRYPTION_KEY` افزونه کار می‌کند اما کلید API با salt وردپرس رمز می‌شود؛ اگر روزی salt عوض شود، کلید غیرقابل بازیابی است و باید دوباره وارد شود. هشدارش را در پیشخوان می‌بینید.

**معیار پذیرش:** سایت بدون خطای سفید بالا می‌آید.

## ۲. نصب تم و افزونه

دو فایل زیپ در پوشهٔ `dist/` مخزن آماده است:

- `clickpop-theme.zip`
- `clickpop-core.zip`

### روش الف — پیشخوان وردپرس (ساده‌ترین)

1. **نمایش ← پوسته‌ها ← افزودن ← بارگذاری پوسته** → `clickpop-theme.zip` → نصب → **فعال‌سازی**
2. **افزونه‌ها ← افزودن ← بارگذاری افزونه** → `clickpop-core.zip` → نصب → **فعال‌سازی**

### روش ب — FTP / SSH

```bash
unzip clickpop-theme.zip -d /path/to/wp-content/themes/
unzip clickpop-core.zip  -d /path/to/wp-content/plugins/
chown -R www-data:www-data /path/to/wp-content/themes/clickpop
chown -R www-data:www-data /path/to/wp-content/plugins/clickpop-core
```
سپس از پیشخوان هر دو را فعال کنید.

### روش ج — WP-CLI

```bash
wp theme install clickpop-theme.zip --activate
wp plugin install clickpop-core.zip --activate
```

**معیار پذیرش:** در پیشخوان منوی جدید **کلیک‌پاپ** با آیکن نمودار دیده می‌شود.
فعال‌سازی افزونه ۱۱ جدول با پیشوند `wp_cp_` می‌سازد:

```sql
SHOW TABLES LIKE 'wp_cp_%';
-- باید ۱۱ ردیف برگردد
```

## ۳. اتصال به سرویس‌دهندهٔ SMM

**کلیک‌پاپ ← تنظیمات**:

| فیلد | مقدار برای فالووران |
|---|---|
| آدرس API | `https://my.followeran.ir/api/v2` |
| کلید API | کلید پنل خودتان (فقط یک‌بار وارد می‌شود، بعد ماسک نمایش داده می‌شود) |
| واحد قیمت | `1000` — یعنی `rate` قیمت هر ۱۰۰۰ عدد است |
| واحد پول | `IRT` (تومان) |
| وضعیت | فعال ✅ |

> ⚠️ **قبل از فروش واقعی، «واحد قیمت» را تأیید کنید.** اگر `rate` در پنل شما قیمت هر ۱ عدد باشد (نه هر ۱۰۰۰)، این عدد را روی `1` بگذارید. اشتباه در این فیلد یعنی ضریب ۱۰۰۰ خطا در قیمت هر سفارش. راه تأیید: یک سرویس ارزان را با `is_test=1` سفارش دهید و مبلغ کسرشده در پنل سرویس‌دهنده را با محاسبهٔ خودتان مقایسه کنید.

**ذخیره** بزنید، بعد **کلیک‌پاپ ← نمای کلی ← همگام‌سازی دستی سرویس‌ها**.

**معیار پذیرش:** در **کلیک‌پاپ ← سرویس‌ها و قیمت** فهرست سرویس‌ها با قیمت تمام‌شده و قیمت فروش دیده می‌شود و ستون «سود» هیچ‌جا منفی نیست.

## ۴. قاعدهٔ سود

همان صفحهٔ تنظیمات:

| فیلد | معنی | پیشنهاد شروع |
|---|---|---|
| درصد سود | روی قیمت تمام‌شده اعمال می‌شود | `20` |
| گام گرد کردن | قیمت نهایی به این گام گرد می‌شود (به بالا) | `100` تومان |
| آستانهٔ جهش قیمت | اگر قیمت سرویس‌دهنده بیش از این درصد بپرد، سرویس خودکار از فروش خارج و به صف بازبینی می‌رود | `20` |

فرمول: `قیمت فروش = ceil( (قیمت تمام‌شده + سود) / گام ) × گام`

قاعده‌های دقیق‌تر (هر برند، هر دسته، هر سرویس) در جدول `wp_cp_pricing_rules` با اولویت `service > category > brand > global` قابل درج‌اند.

**معیار پذیرش:** بعد از تغییر درصد سود و اجرای دوبارهٔ همگام‌سازی، ستون «قیمت فروش» تغییر کرده باشد.

---

## ۵. درگاه پرداخت (زرین‌پال)

همان صفحهٔ تنظیمات، بخش درگاه:

1. تیک **فعال‌سازی** را بزنید.
2. **کد پذیرنده** را وارد کنید (۳۶ کاراکتر، از پنل زرین‌پال).
3. برای تست، تیک **محیط تست** را بزنید.
4. حداقل/حداکثر شارژ را تعیین کنید.

آدرس بازگشت به‌صورت خودکار ثبت می‌شود:
```
https://clickpop.ir/clickpop-payment/zarinpal/
```
اگر بعد از فعال‌سازی خطای ۴۰۴ گرفتید: **تنظیمات ← پیوندهای یکتا** را باز کنید و بدون تغییر **ذخیره** بزنید (بازنویسی قواعد rewrite).

**معیار پذیرش:** در داشبورد کاربر، تب «کیف پول» → مبلغ → «انتقال به درگاه» شما را به صفحهٔ زرین‌پال می‌برد و بعد از پرداخت با پیام سبز برمی‌گردد.

---

## ۶. ساخت صفحهٔ داشبورد

1. **برگه‌ها ← افزودن برگه** با عنوان «داشبورد».
2. در محتوا فقط این شورتکد را بگذارید:
   ```
   [clickpop_dashboard]
   ```
3. در پنل کناری، **قالب** را روی **داشبورد کلیک‌پاپ** بگذارید (تمام‌عرض، بدون سایدبار).
4. انتشار.
5. برگردید به **کلیک‌پاپ ← تنظیمات ← صفحهٔ داشبورد** و همین برگه را انتخاب و ذخیره کنید.

شورتکدهای دیگر:

| شورتکد | کاربرد |
|---|---|
| `[clickpop_dashboard]` | داشبورد کامل: سفارش جدید، سفارش‌ها، کیف پول، تیکت |
| `[clickpop_order_form]` | فقط فرم ثبت سفارش (برای صفحهٔ فرود) |
| `[clickpop_services]` | جدول عمومی سرویس‌ها و قیمت‌ها |

**معیار پذیرش:** با یک حساب کاربری عادی وارد شوید؛ داشبورد با موجودی صفر و فرم سفارش پرشده از سرویس‌های واقعی دیده می‌شود.

## ۷. کرون سیستمی (اجباری)

بدون این مرحله، وضعیت سفارش‌ها به‌روز نمی‌شود و بازگشت وجه خودکار اجرا نمی‌شود.

```bash
crontab -e
```
این خط را اضافه کنید (هر دقیقه):
```
* * * * * cd /path/to/wordpress && /usr/bin/php wp-cron.php >/dev/null 2>&1
```
یا با WP-CLI:
```
* * * * * /usr/local/bin/wp cron event run --due-now --path=/path/to/wordpress >/dev/null 2>&1
```

کارهای زمان‌بندی‌شده:

| هوک | دوره | کار |
|---|---|---|
| `clickpop_sync_services` | هر ۶ ساعت | همگام‌سازی فهرست و قیمت سرویس‌ها |
| `clickpop_sync_orders` | هر ۵ دقیقه | به‌روزرسانی وضعیت سفارش‌ها + بازگشت وجه ناقص/لغو |
| `clickpop_reconcile_orphans` | هر ۵ دقیقه | تعیین تکلیف سفارش‌هایی که پاسخ سرویس‌دهنده گم شده |

**معیار پذیرش:**
```bash
wp cron event list | grep clickpop
```
هر سه هوک با زمان اجرای آینده دیده شوند.

## ۸. منو، لوگو و صفحهٔ اصلی

1. **نمایش ← سفارشی‌سازی ← هویت سایت**: لوگو را بگذارید (اگر نگذارید، لوگوی SVG برند به‌صورت درون‌خطی رندر می‌شود — سریع‌تر است).
2. **نمایش ← فهرست‌ها**: سه جایگاه در دسترس است — «منوی اصلی»، «منوی فوتر»، «منوی قوانین».
3. **تنظیمات ← خواندن**: یک برگه را به‌عنوان صفحهٔ اصلی انتخاب کنید.

### ساخت صفحهٔ اصلی با المنتور

برگهٔ صفحهٔ اصلی را با المنتور باز کنید. در جست‌وجوی ویجت‌ها، دستهٔ **کلیک‌پاپ** را باز کنید:

| ویجت | کار |
|---|---|
| **هیرو کلیک‌پاپ** | تیتر، توضیح و دو دکمه |
| **شبکهٔ سرویس‌ها** | کارت پلتفرم‌ها با «شروع قیمت از» یا کارت سرویس‌ها — قیمت‌ها زنده از دیتابیس |
| **مراحل کار** | سه مرحلهٔ فرایند (تکرارشونده) |
| **شمارنده‌های آماری** | اعداد با انیمیشن، غیرفعال روی `prefers-reduced-motion` |
| **پرسش‌های پرتکرار** | آکاردئون قابل‌دسترس + تولید خودکار `FAQPage` schema |

با **Elementor Pro** می‌توانید هدر و فوتر را هم با Theme Builder بسازید؛ تم به‌صورت خودکار جای هدر/فوتر پیش‌فرض خود را به آن‌ها می‌دهد.

## ۹. تست پذیرش قبل از افتتاح

این هفت تست را دقیقاً اجرا کنید. هرکدام یک باگ واقعی را می‌گیرد.

| # | تست | نتیجهٔ درست |
|---|---|---|
| ۱ | با کاربر A وارد شوید، سفارش ثبت کنید. با کاربر B آدرس `/wp-json/clickpop/v1/orders/{id}` سفارش A را باز کنید | `404` — نه دادهٔ سفارش |
| ۲ | موجودی را روی مبلغی بگذارید که فقط یک سفارش کفاف دهد، و دکمهٔ ثبت را ۵ بار سریع بزنید | دقیقاً **یک** سفارش ثبت شود، موجودی یک بار کسر شود |
| ۳ | یک شارژ موفق انجام دهید، سپس آدرس بازگشت (`?Authority=…`) را دوباره در مرورگر باز کنید | پیام «قبلاً ثبت شده» — موجودی دوباره اضافه **نشود** |
| ۴ | در فرم سفارش، لینک `https://evil.com/?x=instagram.com` بدهید | خطای «دامنهٔ لینک با سرویس انتخابی هم‌خوان نیست» |
| ۵ | با DevTools مبلغ را در درخواست دستکاری کنید | مبلغ سرور اعمال شود، نه مقدار ارسالی |
| ۶ | کلید API را عمداً غلط کنید و ۵ بار همگام‌سازی بزنید | مدارشکن باز شود و پیام «ارتباط موقتاً قطع است» بیاید — نه کسر پول |
| ۷ | یک سفارش را دستی در جدول به `partial` با `remains` نصف تعداد ببرید و کرون را اجرا کنید | نصف مبلغ به کیف پول برگردد و ردیف `refund` در دفتر کل ثبت شود |

## ۱۰. بهینه‌سازی نهایی (اختیاری ولی مؤثر)

```bash
# Redis برای object cache
wp plugin install redis-cache --activate && wp redis enable

# ایندکس‌ها را بررسی کنید
wp db query "SHOW INDEX FROM wp_cp_orders"
```

روی Nginx، بایپس کش برای کاربران واردشده:
```nginx
set $skip_cache 0;
if ($http_cookie ~* "wordpress_logged_in") { set $skip_cache 1; }
location ~ ^/clickpop-payment/ { set $skip_cache 1; }
```

فونت: فایل `Vazirmatn-Variable.woff2` را در `wp-content/themes/clickpop/assets/fonts/` بگذارید تا `preload` فعال شود (اگر نباشد، تم بی‌صدا از فونت سیستم استفاده می‌کند).

## ۱۱. عیب‌یابی

| نشانه | علت محتمل | راه‌حل |
|---|---|---|
| «سرویس‌دهندهٔ فعالی تنظیم نشده» | کلید API ذخیره نشده | تنظیمات ← کلید API را دوباره وارد و ذخیره کنید |
| فهرست سرویس خالی | همگام‌سازی اجرا نشده یا کلید غلط | نمای کلی ← همگام‌سازی دستی؛ ستون «تأخیر آخرین پاسخ» را ببینید |
| وضعیت سفارش‌ها به‌روز نمی‌شود | کرون سیستمی تنظیم نشده | مرحلهٔ ۷ |
| بازگشت از درگاه ۴۰۴ | قواعد rewrite بازنویسی نشده | تنظیمات ← پیوندهای یکتا ← ذخیره |
| «موجودی کیف پول کافی نیست» با وجود موجودی | مبلغ سفارش با قیمت جدید محاسبه شده | همگام‌سازی را اجرا و قیمت را در صفحهٔ سرویس‌ها بررسی کنید |
| قیمت‌ها ۱۰ برابر یا یک‌دهم | «واحد قیمت» یا «واحد پول» اشتباه | مرحلهٔ ۳ — هشدار قرمز |
| هشدار کلید رمزنگاری در پیشخوان | `CLICKPOP_ENCRYPTION_KEY` تعریف نشده | مرحلهٔ ۱ |
| سرویس با وضعیت `review` | قیمت سرویس‌دهنده بیش از آستانه پریده | قیمت را بررسی و در دیتابیس وضعیت را به `active` برگردانید |

لاگ فراخوان‌های API در جدول `wp_cp_api_log` است (بدون کلید API و بدون لینک کاربر). گزارش ممیزی اعمال حساس در `wp_cp_audit_log`.

## ۱۲. آنچه هنوز پیاده نشده

صادقانه، تا تصمیم شما:

- **ورود با موبایل و کد یک‌بارمصرف (OTP):** جدول و طراحی‌اش در سند معماری هست، اما پیاده‌سازی به انتخاب پنل پیامکی نیاز دارد. فعلاً ورود استاندارد وردپرس کار می‌کند.
- **درگاه‌های آیدی‌پی/نکست‌پی:** معماری درایورپذیر آماده است؛ افزودن هرکدام حدود ۱۰۰ خط است.
- **پاسخ کارکنان به تیکت از پنل ادمین:** کاربر می‌تواند تیکت بزند و ببیند؛ رابط پاسخ‌دهی ادمین در فاز بعد.
- **صفحه‌بندی جدول سفارش‌ها در فرانت:** فعلاً ۲۰ سفارش آخر.
- **ترجمهٔ en/ru/zh:** همهٔ رشته‌ها i18n-شده‌اند اما فایل `.po` هنوز تولید نشده.
